# AI Agent (智能体)

大语言模型（LLM）本身是一个“无状态的文本生成器”，没有真实的记忆、无法进行持续的主动规划、也无法直接操作现实世界。

**AI Agent（智能代理）** 则是以大语言模型为核心决策“大脑”，并为其配备了规划（Planning）、记忆（Memory）与工具箱（[[MCP-Core-Protocol-Elements|Tools]]），使其能够在物理或数字世界中主动分析、拆解并执行复杂现实任务的自主实体系统。

---

## 1. 智能体的核心组成部分
```text
                  ┌────────────────────────┐
                  │       大语言模型       │ (推理与规划大脑)
                  └───────────┬────────────┘
                              ▼
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
  ┌───────────┐         ┌───────────┐         ┌───────────┐
  │   规划    │         │   记忆    │         │   工具    │
  │ (Planning)│         │ (Memory)  │         │  (Tools)  │
  └───────────┘         └───────────┘         └───────────┘
```

- **规划 (Planning)**：
  - *子任务拆解*：智能体能将用户的宏观目标（如“策划一次十天旅行”）自动拆解为可操作的小子任务（查天气、定机票、找平替）。
  - *反思与修正*：在执行中遇到挫折时（如工具报错、预算超支），能启动 ReAct（Reasoning + Acting）环路，反思问题并动态修正下一步方案。
- **记忆 (Memory)**：
  - *短期记忆*：维护当前会话的对话历史和执行状态，确保交互连贯。
  - *[[LangGraph-Long-Term-Memory|长期记忆]]*：跨越多次会话，持久化沉淀用户的偏好习惯、用户画像（如喜欢哪类酒店、讨厌红眼航班）。
- **工具 ([[MCP-Core-Protocol-Elements|Tools]] / Actions)**：
  - 智能体的“手脚”。允许智能体调用计算器、外部搜索引擎（如 Tavily）、关系数据库及智能家居的 API，将推理意图转化为物理世界的实际操作。

---

## 2. 智能体的五层技术架构
1. **基础模型层**：提供基础逻辑推理的大语言模型（如 GPT-4o、DeepSeek-V3、Qwen-Plus）。
2. **提示词/人设层**：定义智能体的角色、性格边界、行动准则与安全要求。
3. **工具与动作层**：封装可供调用的 Python 函数、API 接口和沙箱运行环境。
4. **运行与控制层**：智能体执行引擎（如 **[[LangChain-Agent-Runtime]]**、**[[Agent-Middleware]]**），管理状态流转与并发。
5. **协作系统层 (MAS)**：多智能体协作框架，定义个体之间如何以团队方式互通协作。

---

## 3. 多智能体协作系统 (MAS) 四大核心设计模式

| 模式 | 运作控制特点 | 上下文管理与适用场景 |
| :--- | :--- | :--- |
| **SubAgents (子代理)** | **集中控制**。主 Agent 作为 Supervisor 绝对控制控制流，把子 Agent 封装为 [[MCP-Core-Protocol-Elements|Tools]] 调用。 | **强上下文隔离**。子代理细节不会污染主代理上下文。适合工具众多、需要分步骤执行的统筹场景。 |
| **[[LangGraph-Multi-Agent|Handoffs]] (移交模式)** | **分布式流转**。当前 Agent 发现超出自身职责时，通过转交工具将控制权移交给新 Agent。 | **多轮接管**。新 Agent 直接与用户接管多轮对话，适合售后客服流转、阶段式推进的复杂问答。 |
| **Skills (技能模式)** | **单Agent，多套技能**。智能体人设与记忆完全共享，依据用户意图动态 `load_skill` 规则提示词。 | **记忆完全共享**。没有上下文隔断，能始终保持统一的拟人化交互，适合 SQL 查询、资料检索。 |
| **Router (路由器模式)** | **先分发，再汇总**。Router 仅负责意图识别分流，分发给对应子 Agent 并行执行并汇总。 | **单次分发**。Router 自身无业务逻辑，适合多源信息并行汇总。 |
