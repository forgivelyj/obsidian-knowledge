# Parent-Child Index (父子/层级索引)

在[[Naive-RAG|朴素 RAG]] 系统中，分块大小（Chunk Size）是一个极其尴尬的超参数：
- **分块过小**（如 128 tokens）：向量检索的精度非常高（因为信息聚焦，没有噪声），但由于上下文严重断裂，大模型回答问题时容易断章取义。
- **分块过大**（如 2048 tokens）：上下文极其完整，但语义会被大量无关信息稀释，导致向量检索失败，且塞入大模型时会浪费很多无关 Token。

**父子索引（Parent-Child Index）** 是一种层级化索引的艺术，实现了“小分块检索（精确对齐） + 大分块返回（上下文完整）”的级联召回效果。

---

## 1. 层级切割与双向关联
在数据准备阶段，我们使用 `HierarchicalNodeParser` 将文档进行树状分层切分，并通过 `relationships` 元数据在父子节点间建立指针关联：

```text
               ┌──────────────────────────────┐
               │    Document (源长文档)        │
               └──────────────┬───────────────┘
                              ▼
               ┌──────────────────────────────┐
               │  Parent Node (父节点, 2048)   │
               └──────┬───────────────┬───────┘
                      ▼               ▼
         ┌───────────────┐ ┌───────────────┐
         │ Child Node-1  │ │ Child Node-2  │ (子节点, 512)
         └───────┬───────┘ └───────┬───────┘
                 ▼                 ▼
          ┌─────────────┐   ┌─────────────┐
          │ Leaf Node-1 │   │ Leaf Node-2 │ (叶子节点, 128) ──► 仅在此层生成向量索引
          └─────────────┘   └─────────────┘
```

- **存储策略**：全量层级节点（包括大父节点和小叶子节点）都存放在原始文档库（Docstore）中。
- **向量索引策略**：**仅为最小的叶子节点（Leaf Nodes）计算 [[Embedding]] 并写入[[Vector-Database|向量数据库]]。**

---

## 2. AutoMerging 自动合并检索机制
当用户提出问题并执行查询时：
1. **向量检索**：先在[[Vector-Database|向量数据库]]中检索，召回最相似的前 $N$ 个**叶子节点**（Leaf Nodes）。
2. **自动合并（Auto Merging）**：通过 **`AutoMergingRetriever`** 进行层级回溯：
   - 检索器从命中的叶子节点出发，沿父子指针向上寻找它们的父节点。
   - 算法计算每个父节点下属的子/叶子节点在此次检索中的**召回比例**。
   - 如果一个父节点下属的叶子节点被命中的比例超过了指定的阈值（如 `simple_ratio_thresh=0.5`，即超过半数），检索器就会**舍弃这群散落的小叶子节点，转而直接将它们上层的父节点（Parent Node）的大段文本全部捞出**作为上下文。
3. **效果**：用最敏感的微型向量感知并捕捉问题，但给大模型提供足够大、足够连贯的信息段落，完美消除了分块大小的选型矛盾。
