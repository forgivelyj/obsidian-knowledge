# [[RAG]] Workflow Platform ([[RAG]] 工作流平台)

在 [[RAG]] 系统的落地进程中，开发者面临着“选择底层库纯代码手写（如 [[LlamaIndex]]、LangChain）”与“选择图形可视化工作流平台编排”的路线抉择。

**[[RAG]] 工作流平台** 通过把大模型交互、文件分块解析、知识库检索与外部 API 工具等底层细节进行组件化，允许开发者通过“低代码拖拽式拓扑图”的方式，快速拼装并发布生产级 AI 应用。

---

## 1. 纯代码开发与工作流平台对比

| 对比维度 | 纯代码开发 ([[LlamaIndex]] / LangChain) | 可视化工作流平台 ([[Dify]] / FastGPT) |
| :--- | :--- | :--- |
| **开发与迭代速度** | ❌ 较慢，需要从零搭建完整的数据流和网络交互。 | ✅ 极快，大部分功能模块开箱即用，支持一键发布。 |
| **定制化能力** | ✅ 极高，开发者可以深入内核重写任何检索或排序算法。 | ❌ 较低，受限于平台已封装的节点类型与插件功能。 |
| **工程复杂度** | ❌ 高，需要自行处理会话状态、并发安全、监控审计。 | ✅ 低，平台在后台自动化实现用户管理、日志监控。 |
| **调优上限** | ✅ 强，支持针对底层硬件、私有向量库做极致深度优化。 | ❌ 弱，难以调整平台闭源部分的底层超参数。 |
| **数据隐私控制** | ✅ 绝对掌控，支持彻底本地化私有化物理隔离部署。 | ❌ 受限，可能需要依赖云端托管平台的数据合规策略。 |
| **最佳适用场景** | 超大规模、定制化关系逻辑复杂的核心核心业务知识库。 | 中小规模、要求快速验证落地响应的 MVP 或 PoC。 |

## 2. 主流四大开源 [[RAG]] 平台横向解析

### ① 网易有道 QAnything
- *核心理念*：**极度强调两阶段检索机制与精排（[[Reranking|Rerank]]）**。
- *技术亮点*：官方推荐使用定制的 `bce-embedding-base_v1`（[[Embedding|嵌入]]向量）和 `bce-reranker-base_v1`（[[Reranking|重排]]模型）的强悍组合。其将 `Rerank` 提升至第二重召回的极高地位，显著提高问答准确度。

### ② Infiniflow RagFlow
- *核心理念*：**Quality in, quality out（垃圾进，垃圾出）**。
- *技术亮点*：为了从根源上斩断文档分片时的排版破损（如表格断裂、图表串行），RagFlow 放弃了市面主流的 [[RAG]] 中间件，自研了一整套深度的“文档物理版面智能分析系统（Layout Analysis）”，专注于高精度还原复杂非结构化文件的原始排版。

### ③ Labring FastGPT
- *核心理念*：**数据预处理阶段的高强度模型干预**。
- *技术亮点*：在非结构化文档分段入库时，FastGPT 支持利用大模型对切段后的文本进行“问答对自动生成”（Q&A 模式）。相比普通分段，大模型生成的问题库向量在检索时对用户提问的匹配效率能提高数十个百分点。

### ④ LangGenius [[Dify]]
- *核心理念*：**一站式企业级可视化 AI 管道与 Agent 编排**。
- *技术亮点*：[[Dify]] 是目前生态最庞大的编排系统。通过丰富的内置逻辑节点（意图识别分类器、Jinja2 模板转换、人工审核干预等）和强大的 Agent 外部工具生态，使用户能通过低代码实现极为复杂的人机协作工作流。
