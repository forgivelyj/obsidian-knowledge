# Reranking (重排)

在 [[RAG]]（[[RAG|检索增强生成]]）系统中，**重排**是目前提升检索精准度、减少大模型输入噪声**性价比最高**的手段。

---

## 1. 为什么需要重排？
传统的向量相似度匹配（如 Cosine 余弦）为了追求速度，使用**双编码器（Bi-Encoder）**架构：分别计算问题向量和文档向量，然后快速计算内积。
- *局限*：问题向量与文档向量在编码时彼此独立，没有相互“交互”，这导致检索召回的 Top-K 粗筛列表中包含很多语义相似但与实际答案无关的“干扰噪声”。
- *大模型痛点*：直接增加 Top-K 会导致 Prompt 注入大量无用数据，触发 LLM 的“中间迷失”缺陷（大模型只关注 Prompt 首尾，忽略了中间真正的答案），且极大消耗 Token 成本。

---

## 2. 两阶段检索工作流（过召回与精排）
重排技术引入了“粗筛 + 精筛”的两阶段漏斗模型：

```text
向量数据库 ──► 1. 粗筛阶段 (双编码器) ──► 召回 Top-N (如 N=30, 速度极快)
                                                  │
                                                  ▼
最终 LLM ◄── 3. 取前 K 个 (如 K=3) ◄── 2. 精排阶段 (重排模型/交叉编码器)
```

1. **粗筛（Retrieval）**：利用高维向量库快速进行 ANN 搜索，召回范围略大的 Top-N 个文档片段（N 通常在 20-50 之间）。
2. **精排（Reranking）**：将用户问题与这 N 个文档片段两两成对输入给**交叉编码器（Cross-Encoder）**模型。
   - Cross-Encoder 让问题中的每个词和文档中的每个词在注意力层进行深度交互，计算出高精度的相关性分数。
3. **裁切生成**：过滤出重排后分数最高的 Top-K（K 通常为 3-5）文档作为上下文，送入大模型生成最终答案。

---

## 3. 常见重排模型
- **Cohere Rerank**：企业级托管重排 API 服务，效果极佳。
- **bge-reranker-large / bge-reranker-base**：北京人工智能研究院（BAAI）开源的高性能本地部署重排模型，对中英文支持优异。
