# Dify 应用开发平台

Dify 是大模型生态中占据统治地位的低代码[[RAG-Workflow-Platform|编排平台]]之一。它为开发者屏蔽了底层的模型适配细节，以可视化的连接方式极大地降低了 AI 管道与 Agent 系统的开发难度。

---

## 1. 核心应用模式
在 Dify 平台中，应用通常被划分为以下三大核心类型：
- **聊天助手 (Chatbot)**：支持多轮自然语言对话，内置对话历史上下文机制（Memory）与会话变量存储，最适合用来构建在线客服或问答机器人。
- **文本生成 (Text Generator)**：属于“投币式”单次自动化写作能力模块（如文章自动翻译、代码转换器）。每次运行都是独立的、全新的一次交互，没有对话记忆负担。
- **Agent ([[AI-Agent|智能体]])**：基于 ReAct 等推理策略。开发者只需给大模型配置好“系统指令（System Prompt）”和相关的 API “工具（[[MCP-Core-Protocol-Elements|Tools]]）”，大模型就会自动拆解用户问题，自主决定执行哪些外部工具并合成最终答案。

---

## 2. 工作流 (Workflow/ChatFlow) 核心节点详解

Dify 的可视化画布通过将复杂的逻辑抽象为“节点（Node）”，允许通过节点拖拽组装复杂的业务线：

```text
  [Start (开始)] ──► [Intent Classifier (分类)] ──┬──► (知识问答路径) ──► [Knowledge Retrieval (知识检索)]
                                                   └──► (日常聊天路径) ──► [LLM (大模型回复)]
```

### ① 意图分类器 (Intent Classifier / 问题分类器)
- *作用*：对用户的输入内容进行语义分析，并智能判断其归属。
- *配置*：开发者在节点中定义多个类别并书写相应的描述或示例。节点执行后，会根据大模型的分类结果，将流程分流到对应的后置逻辑分支（如将“怎么用”分流到知识库问答，将“你好”分流到打招呼话术）。

### ② 模板转换 (Template)
- *作用*：利用著名的 **Jinja2 模板引擎**，将来自上游各个不同逻辑分支的“杂乱变量”拼接整合为规范的文本。
- *优势*：能高效实现形如 `{{target_language}} 翻译: {{code_snippet}}` 的 Prompt 组装。

### ③ 变量聚合器 (Variable Aggregator)
- *作用*：在工作流中存在复杂的条件分支（如多路分支且只有一条路生效）时，用来将各分支输出的同类变量进行“聚拢归一”。
- *意义*：统一聚合为一个合并变量，避免下游节点在引用变量时需要面对一长串不同分支产生的异构字段。

### ④ 参数提取器 (Parameter Extractor)
- *作用*：大模型往往返回冗长难懂的段落。参数提取器使用大模型的 **Structured Output (结构化输出)** 能力，能精准地从一大段自由文本中抠出指定的关键参数（并转为 JSON 格式），直接喂给下游的 HTTP 节点或外部 API。

### ⑤ 循环与迭代节点 (Loop & Iteration)
- **迭代节点 (Iteration)**：针对上游传递来的列表数据进行 for-each “挨个元素处理”（例如拿到 10 篇新闻链接，迭代逐一请求详情）。
- **循环节点 (Loop)**：基于特定的循环控制变量，重复执行某一组节点，直至条件满足为止。

### ⑥ 人工介入节点 (Human-in-the-loop)
- *作用*：在敏感业务（如合同生成、大额转账、数据删除）中，流程流转到该节点时会自动挂起暂停。
- *机制*：管理员可在 WebApp 界面中输入反馈、录入表单或点击“同意/拒绝”按钮，流程收到响应后，才会携带人工输入的数据恢复继续运行。
